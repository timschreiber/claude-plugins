## Outline bullet 1: `run-report` script and `tests/orcastrat/run-report.bats`

- Script location/invocation follows D04: `plugins/orcastrat/scripts/run-report`, invoked `bash "${CLAUDE_PLUGIN_ROOT}/scripts/run-report" <plan-dir>` (D05 signature: `run-report <plan-dir>`).
- Error/exit conventions (D55, matches every other script): exit 0 after writing the report; on usage error, `<plan-dir>` not a directory, or `<plan-dir>` outside a git work tree, print one `error: <message>` line to stderr, nothing to stdout, exit 2. Compare `plugins/orcastrat/scripts/task-brief:24-36` and `plugins/orcastrat/scripts/run-state:60-72`.
- Path printing (D43/D44/D53): every path the script prints goes through `print_path` from `plugins/orcastrat/scripts/lib/common:8-14`, sourced with `. "$(dirname "${BASH_SOURCE[0]}")/lib/common"`.
- Bash 3.2 compatible, no associative arrays/`mapfile`/`${var,,}` (spec §20 rule, D04 family).
- **Input data it reads** (spec §12 bullet 1, M11 Context):
  - Task statuses and `- Escalated:`/`- Blocked:`/`- Re-tiered:`/`- Interrupted:` lines in milestone files (formats defined at `plans/orcastrat-execution/plan.md` D84, D87, D90, D31).
  - `Orcastrat-Task:`/`Orchestratinator-Task:` commit trailers (D80: success commit `chore(plan): <task ID> done` with `Orcastrat-Task: <task ID>` trailer; `recover` already parses both trailers, `plugins/orcastrat/scripts/recover`).
  - Failure logs `notes/<task ID>-failures.md`, entry format fixed by D87: `## Attempt <n>` heading, then `- Tier:`, `- Time:`, `- Description:`, `- Hypothesis:`, `- Fixes tried:`, `- Then: resumed | escalated to <tier> | resume failed (<error>), escalated to <tier> | redispatched at <tier> (interrupted) | blocked (STUCK)`, `- Error:`.
  - `notes/run-log.md` lines, all `key <UTC> ...` shaped, one per line (D88, D42, D49, D186, run-state script):
    - `start <UTC> <plan-dir>` / `end <UTC> <PAUSE|STOP|COMPLETE> <reason>` (`run-state:90,114`, D88).
    - `model-notice <UTC> <model ID>` (D42; `plugins/orcastrat/skills/run/SKILL.md:136,190`).
    - `background-warning <UTC> <agent> <task or milestone ID> "<notice text>"` (D49; `SKILL.md:30`).
    - `already-integrated <UTC> <task ID>` (`SKILL.md:354`).
    - `containment-fallback <UTC> <milestone ID> wave <n>` (D186).
  - Review notes `notes/<ID>-review.md` / `-review-2.md`, `notes/<ID>-plan-review.md`: `## Blocking` / `## Advisory` (milestone-reviewer/reviewer) or `## Issues` (plan-reviewer) sections. **Current** finding line format (post-M10, what M11-onward reviews will produce): `- [<score>] <category>: <path:line> — <problem> (<task ID, Coverage row, or D<nn>>)` (`plugins/orcastrat/agents/milestone-reviewer.md` Report section). After **Validate a review** (`SKILL.md:46,54-56`) a validated candidate's leading `[<score>]` becomes `[<score>/<validator score>]` or `[<score>/none]`; a downgraded one moves to `## Advisory` with ` — validator: <reason>` or ` — validator: no score` appended, and stays a `[<score>/<validator score>]`-tagged line there.
  - **Important:** `plans/orcastrat-execution/notes/M01-review.md` through `M10-review.md` (the plan's own history, built before M10 landed the score/category format) do **not** use the `[<score>] <category>:` shape — they are plain `` - `path:line` — <text> (<task ID>, D<nn>) `` lines with no bracketed score/category (confirmed in `notes/M09-review.md` and `notes/M10-review.md`). `run-report`'s own bats fixtures should use the current (post-M10) format since that's what it will encounter from M11 forward; a real run-report run over this repo's own plan would see mixed formats in older notes.
- **Reports, per run invocation and for the plan so far** (spec §12 bullets 2, M11 Context bullet 2): tasks done; attempts/resumes/escalations per tier; STUCK tasks; merges resolved and reruns after failed merges; containment downgrades; auto-decided questions with their Decision (Change 12, lands in M12 — not present in this repo yet, so this section will read as empty/none until M12); advisory findings per milestone and validator confirm/downgrade outcomes; stops and pauses by reason; wall-clock time.
  - "Per run invocation" boundaries come from `notes/run-log.md`'s `start`/`end` line pairs (D88/D89): each `start <UTC> <plan-dir>` through the next `end <UTC> <mode> <reason>` (or EOF, for a run still active) is one invocation.
- **Usage section** (spec §12 bullet, D07): "Usage is summed from the D07 lines. Where none exist, that section says `not available`." **Unconfirmed/gap:** D07 says `run` appends "one line per returned agent to `plans/<slug>/notes/run-log.md` (task or milestone, agent, tokens, duration, from the task notification)" — grepping `plugins/orcastrat/skills/run/SKILL.md` for `tokens`/`duration`/`usage` finds **no such logging step written anywhere in SKILL.md today**. Outline bullet 6 ("`run-report` reports tokens per run invocation from the D07 usage lines (D79, spec §25a item 5)") assumes these lines exist, so M11's tasks likely include adding the append step.

## Outline bullet 2: `run` calls `run-report` at Pause, Stop and completion, commits it

- **Pause** section (`SKILL.md:439-445`): step 1 calls `run-state end PAUSE <reason>`; step 2 commits pending plan-file changes (`git add "<plan dir>"`, `git commit -m "chore(plan): pause at <where>"`). `run-report` needs to run and its output added to this same commit — insert a step between 1 and 2 (or fold into step 2's `git add`), consistent with "commits the report with the pause or stop commit" (spec §12 last bullet).
- **Stop** section (`SKILL.md:449-455`): step 1 `run-state end STOP <reason>`; step 2 commits plan-file changes (`git add <plan dir>`, `git commit -m "chore(plan): blocked at <where>"`) — same insertion pattern. Note step 2's caveat: "In serial mode, if task code is in the main working tree, leave all of it uncommitted, plan files included, for the user to inspect" — `run-report` must still write/commit only under `<plan dir>/notes/`, consistent with that carve-out (it's a plan-dir file, so `git add <plan dir>` already covers it).
- **Completion** (`SKILL.md:400`, "4. Finish the plan" step 2): `run-state end COMPLETE plan`, then `git add "<plan dir>"` and `git commit -m "chore(plan): complete plan"` — same insertion point.
- No end-state section currently mentions `run-report` at all (confirmed by grep — no `run-report` string anywhere in `plugins/orcastrat/` yet, since M11 hasn't built it).
- The "Notes are committed before the next dispatch" rule (`SKILL.md:27`) and the file-edit allowlist at `SKILL.md:21` ("The only files you edit are plan.md, milestone files, the notes files this skill names... and `notes/run-log.md`...") will need `run-report.md` added to that named-files list once `run` starts writing it.

## Outline bullet 3: milestone-end suggestion step and `notes/instruction-suggestions.md`

- **Trigger** (spec §19 item 1, Change 18): "When a finding category (Change 10) appears in the reviews of two or more milestones in a plan." - **Output**: `plans/<slug>/notes/instruction-suggestions.md` (spec §19 item 2), a new notes file not yet created anywhere in this repo (confirmed: `notes/instruction-suggestions.md` doesn't exist under `plans/orcastrat-execution/notes/`).
- **Suggestion content** (spec §19 item 1, M11 Context bullet "Suggestions"): a CLAUDE.md rule with draft wording, or a hook when the rule must hold every time and is checkable by a script. To check whether CLAUDE.md (or another target file) is "already flagged for leanness," `run` would grep that file for a `path:line` whose path matches the target.

## Conventions / repo patterns to follow

- Every script sources `lib/common` for `print_path`, uses `fail() { printf 'error: %s\n' "$1" >&2; exit 2; }`, and validates arg count and directory/git-worktree-ness before doing anything (see `task-brief`, `run-state`).
- `run-report`'s bats tests belong at `tests/orcastrat/run-report.bats`, run via `bash scripts/run-bats.sh tests/orcastrat/run-report.bats` (D02), and must pass `Invoke-Pester`-equivalent gate `./scripts/Validate-All.ps1 && bash scripts/run-bats.sh` per the Milestone verify line.
- Agent file conventions if any new prose/instructions are added to `run`'s SKILL.md: no `$(...)` command substitution in commands Claude is told to run (Change 19 item 3, `SKILL.md` already has a `! grep -qF '$('` Verify pattern used elsewhere, e.g. `plans/orcastrat-execution/M09-preflight-checks.md:917`).
