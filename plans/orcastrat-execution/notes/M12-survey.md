# M12 survey: The decider

## Spec and Decisions (already read in full by the planner via Context; key excerpts)

- Spec §13 (`docs/orcastrat-execution-spec.md:260-288`): agent `decider` (Opus, high, `maxTurns: 40`), read-only except its output file. Input: plan dir, question (with task/milestone), output path `notes/decisions/<question-id>.md`. Reads: question, sources, plan.md Decisions, milestone Context, relevant code. Returns: recommendation + one-line reason or `no recommendation`; label `local`/`stop`. Writes full reasoning to file, replies with status block only. Answers only the question asked — no revisions, no chained decisions; if answering needs another decision first, answer is `no recommendation`.
- `run` uses it for every GAP (worker or planner). `Auto-decide: local` (header field or `--auto-decide`): records `local` recommendation as a Decision, source `auto-decided (<question-id>)`; worker GAP → reset to BASE (no failure-log entry), regenerate brief, retry same tier (not a failed attempt); planner GAP → invoke planner again. `stop` label or `no recommendation` → stop as GAP as today. `Auto-decide: off` (default) → decider still runs, stop report carries recommendation+label. Limit: `Max auto-decisions: <n>` (default 5) per run invocation; reaching it → **Pause** reason `LIMIT` (auto-decisions). Auto-decided items get their own run-report section.
- Spec §1.3 (`docs/orcastrat-execution-spec.md:15`): "The `decider` (Change 12) recommends; only `local` recommendations under `Auto-decide: local` are applied without the user."
- Spec §22 item 3 / D68 (`plan.md:167`): final allowlist — `decider` gets `Read, Glob, Grep, Write`, no shell.

- Dispatch to worker at "same tier" (no escalation): the existing dispatch line at 3d item 1 (`:263`) already takes "the task's current tier" — auto-decide retry keeps the same tier rather than climbing, unlike a normal escalation.

For the planner's GAP auto-decide path ("for the planner's GAP, the planner is invoked again"): the existing re-invoke pattern at item 3 of 3a (`:216`, after a `SCOUT` report) shows the call shape `Plan: <plan dir>` / `Milestone: <ID>` reused for re-invocation — the planner is called with the same two lines (no special "Auto-decided:" line is documented anywhere yet; nothing in Context specifies one, so the exact recall message the planner needs to notice the new Decision is unconfirmed/undecided by outline — likely just relies on Decisions being read fresh, since D101 says a brief/dispatch is regenerated from "plan files alone").
