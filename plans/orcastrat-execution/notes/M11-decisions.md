# M11 decisions: full text

The full question and option text behind D207 and D209, as asked at the M11 stop. The user chose option (a) of each. For D209, `suggest-check` only detects and counts categories, and `run` drafts the rule or hook wording.

## D207: run-report invocations, counts and layout (M11 question 4)

- (M11) [ambiguous] How `run-report` assigns records to invocations, how it defines its counts, and how the report is laid out.
  Where: spec §12 ("per run invocation and for the plan so far"; "attempts, resumes, and escalations per tier"; "tasks done"; "wall-clock time"; "advisory findings per milestone, and blocking candidates confirmed or downgraded"); D87 (attempt numbering); D182 (finding line shapes); `notes/M11-survey.md` bullet 1 (this plan's own M01–M10 reviews predate D182's shape).
  Options: (a) An invocation runs from a `start` line to the next `end` line (or the next `start`, or the end of the log). Run-log lines and failure-log entries (`- Time:`) belong to the invocation whose span holds their UTC time; commits (trailer commits, the commit that added a review note) by committer time; an uncommitted review note belongs to the last invocation. Tasks done: per invocation, commits carrying `Orcastrat-Task:` or `Orchestratinator-Task:`; for the plan, tasks with `- Status: done`. Attempts per tier: failure-log entries at their `- Tier:`, plus one successful attempt per task done, at its current tier (D84). Resumes: entries whose Then is `resumed`. Escalations: entries whose Then contains `escalated to`, at their `- Tier:`. STUCK: entries whose Then ends `blocked (STUCK)`. Wall-clock: `end` minus `start` per invocation, `unknown` without an `end` line; the plan's is their sum. Review counts use D182's shapes only, so lines in other shapes aren't counted: advisory = findings under `## Advisory`; confirmed = candidates left under `## Blocking` or `## Issues` with a `[<score>/<validator score>]` tag; downgraded = Advisory findings containing ` — validator: `. Layout: `# Run report: <plan title>`, one `## Invocation <k>: <start UTC>` section per invocation and a `## Plan so far` section, each with the same bullets in spec §12's order, then `## Usage`, `## Model notices`, `## Suggestions`. (b) As (a), but only run-log events are reported per invocation; everything else is for the plan so far. recommended: (a), it gives every count both ways from records that exist today.

## D209: the suggestion step (M11 question 6)

- (M11) [insufficient] The suggestion step (Change 18): which reviews count, how `run` finds a recurring category, where the suggestion goes, and when an instruction file counts as flagged for leanness.
  Where: spec §19 items 1–3 and Acceptance ("the same category in two milestone reviews produces one suggestion with draft wording"); D184 (Conventions findings feed Change 18); D198 (category tags); `plugins/orcastrat/reference/instruction-review.md` (`.orcastrat/instructions/review.md`'s `## Findings`); `notes/M11-survey.md` Unconfirmed item 4.
  Options: (a) A milestone's reviews are its milestone review and re-review (`notes/<ID>-review*.md`) and its per-task reviews (`notes/reviews/<ID>-T*.md`), both sections, not its plan review, which reviews the plan rather than the code. A new script `suggest-check <plan-dir>` (D04 naming, D55 errors) prints one line `<category> <milestone IDs>` for each category found in two or more milestones' reviews that isn't yet a `## <category>` heading in `notes/instruction-suggestions.md`, or `OK`, so `run` never reads review notes. In 3f item 7, before the `complete <ID>` commit, `run` runs it and appends one section per printed category: `## <category>`, `- Milestones: <IDs>`, `- Kind: rule | hook`, `- Target: CLAUDE.md`, `- Leanness: flagged; a hook or skill is preferred | not flagged`, `- Draft:` and the draft wording in a `text` fence. A category gets one suggestion ever. The target is flagged when `.orcastrat/instructions/review.md` exists and its `## Findings` section cites the target's path; with no `review.md`, it isn't flagged. `run-report`'s `## Suggestions` lists each heading with its Kind and Target. (b) As (a), but `run` greps the review notes itself instead of a script. (c) As (a), counting plan reviews too. recommended: (a), the counting is mechanical bookkeeping, which spec §7 gives to scripts.
