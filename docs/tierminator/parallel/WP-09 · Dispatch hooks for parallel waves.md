Work package WP-09 · Dispatch hooks for parallel waves

Goal: H4 dispatches, judges, retries and resumes the workers of a parallel wave, each in a worktree that tierminator made, and the worker agents run the plan's setup commands there.

Depends on: WP-01, WP-06, WP-07, WP-08.
Spec sections: The dispatch of one task; Judging a task; Setup; State; Notices.

Scope:
- h4-dispatch.js stays as it is for serial waves. When the run state has a wave, each mode hands over to a new lib file (for example lib/h4-wave.js). Every change to the wave state goes through state.update.
- pre: find the slot from the Task: line, check it through checkDispatch, then make the slot's worktree with worktreeAdd (WP-06) at the slot's recorded wave base, serialized through the state lock (the probe's three hook processes ran one after another, but do not rely on it). The Agent call is not changed: no isolation, no updatedInput, no permissionDecision on success. A failed worktreeAdd denies the call with Git's message, and the slot's outcome is the fatal "WORKTREE CREATE:" of WP-08. The main tree is not reset.
- Learn the agent id: the slot of a worker is the `Task:` line in the first message of its transcript (`agent_transcript_path` on SubagentStop; the probe's slotOfAgent did this correctly in every run), or PostToolUse on Agent when it arrives first. Join through state.update with recordAgent (WP-08). No SubagentStart hook is needed.
- stop and the hand-back path: judge the slot from its report and from Git at its known worktree path (one commit since the wave base, the Tierminator-Task and Tierminator-Plan lines, a clean tree, still on its own branch `tierminator/<runId>/<task>`), and check that the main tree is still on the wave base with an empty status (the fatal "MAIN TREE:" of WP-08); claim the attempt per slot; a retry discards the slot's worktree and branch (worktreeRemove and branchDelete) and the next dispatch makes a fresh one; record the notice. In auto mode SubagentStop carried no `last_assistant_message` in the probes (findings): the report must come from the transcript when it is absent, which the serial path may already do; check it and add a test. No reset --hard in a parallel wave.
- post, failure and the three resume modes work per slot: a SendMessage is matched to a slot by agent id.
- Audit every reader of `state.current` and make each handle a wave state (spec, "Readers of `state.current`"): h1-plan-rules.js (the hand-back and turn-limit notes), h4-dispatch.js (each mode hands over to the wave path before it reads `current`), h5-guard.js (the stop and edit guards, resumeDue), h7-limit.js through lib/result.js (`currentId`, and `run = ... && !!s.current`), and lib/spend.js (`recordAttempt` and `outcomeOf` read `prev.current` and `currentTask(prev)`; on a wave state its `safe()` wrapper would swallow the error and silently drop the attempt). Spend already reads each worker's own transcript by agent id (`agent_transcript_path`), so no attribution change is needed beyond reading the slot. Start with `grep -n "\.current" plugins/tierminator/scripts/*.js plugins/tierminator/scripts/lib/*.js` and check the list against the spec. One test per reader with a wave state, and a test that an attempt of a wave slot is written to the telemetry file with the right task, tier and attempt.
- h8-worktree-guard.js, new, a PreToolUse hook registered in hooks.json on Bash, PowerShell, Write, Edit, Glob and Grep, from the tested guard.js: only for tierminator's worker agent types while the run state has an active wave, it denies a Bash command that does not start with `cd "<dir>" &&` into the worktrees directory (`<repo>/.claude/worktrees/tierminator-<run>-`), any PowerShell call, a Write or Edit whose path is outside it, and a Glob or Grep whose `path` is missing or outside it. It judges by a path prefix only, so it cannot tell one slot's worktree from another's. It only ever denies (permissionDecision "deny" with a reason the worker can act on) and never grants a permission or rewrites a tool input.
- All six tier agents get a Parallel section in their shared body, the tested `PARALLEL` text of c-runner.js with the setup instruction added: when the message has "Parallel: yes", WT is the path on the `Worktree:` line; run the tasks file's setup commands first, in order, in WT, and stop at the first failure by reporting FAILED with a NOTE starting "SETUP FAILED:"; every Bash command starts with `cd "<WT>" && ` and PowerShell is never used; every Write, Edit and Read takes an absolute path that starts with WT (the tasks file is the exception); every Glob and Grep passes `path` set to WT; never build a path from `pwd` output (Git Bash prints `/tmp/...`, which file tools resolve to the wrong place; P1 lost a write that way); commit on the branch already checked out and never leave WT. The resolver's message (WP-12) uses the same rules. Update agents.test.js (the bodies stay identical).
- When the last slot of a wave settles, the wave is closed in the state and the run halts with the reason "integration is not built yet", so this package is testable alone. WP-11 replaces that stub.
- Tests with real commits for a wave of three: dispatch with the worktrees made, a clean finish, a retry in place while the others run, an exhausted slot halting after its siblings settle, a stale stop, a turn-limit resume per slot, a setup failure being fatal, the Agent call left unchanged on success and denied with Git's message when worktreeAdd fails, a call carrying isolation being denied, the agent id joined in either order, a leaked edit in the main tree failing as "MAIN TREE:", a missing `last_assistant_message`, and the guard hook (each deny case, each allow case, silent outside a wave and for the main session, never a grant). Serial hook tests are untouched.

Out of scope: starting waves (WP-10), the hand-back, stop-guard and display hooks (WP-10), integration (WP-11).
